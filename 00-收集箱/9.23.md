# Git 名词解释

用生活化比喻：Git 像一个**档案保管员**。

## 1. 工作区，暂存区，.git, GitHub

- 你的项目文件夹 = 工作区（你正在编辑的桌面文件，随手改来改去）
- **暂存区 (stage/index)** = 收纳筐，挑选一部分改动，先放进筐子里
- 本地仓库 (.git 文件夹) = 档案室，筐子里的东西正式归档，保存历史版本
- GitHub 网页（远程仓库）= 云端备份档案室
## 2. 操作指令
### 1）` git init 

 把普通文件夹变成 Git 管理的项目，生成隐藏的`.git`文件夹（本地档案室）

- 场景：**本地从零新建项目**，就像你买了一个空档案柜。

> 对应你：`dl‑learning‑journey`仓库就是 init 出来的。

### 2）`git clone` 仓库地址

把网上 GitHub 的完整仓库，下载一份到你电脑本地

- 场景：拿别人现成代码。相当于**把云端档案室整套拷贝一份回家里**。

> 后面复现 SN2N 官方代码就会用到 clone。

### 3）`git add` 送往【暂存区（收纳筐）】

> ⚠️只是放到收纳筐！**还没有保存版本！只是挑选要归档的内容**。 类比：你把纸质文件挑出来，丢进收纳筐，还没有装订入档案。

### 4 `git commit` -m "类型:说明"存入【本地档案室】

把**暂存区（收纳筐）里面所有东西**，正式打包成一个历史版本，存进本地`.git`档案室。 `-m`后面写提交备注，就是档案标签，写明这次改了啥。

> 做完 commit，改动才真正在你电脑上留下历史快照。 👉**commit 只发生在你自己电脑，此时还没有上传 GitHub 网页！**

### 5）`git push` 推送到【云端 GitHub】

把本地档案室的版本，同步上传到 GitHub 网页远程仓库。

> push = 将家里档案，复制一份送到网上云端。

### 6）`git pull `拉取【云端 GitHub】

把 GitHub 网页上面别人更新好的版本，下载同步回你的电脑本地。

> 比如师兄改了仓库，你电脑本地旧了，执行 pull 把云端新档案拿回家。

## 3`.gitignore`

专门告诉 Git：**永远不要把某些文件 / 文件夹放进工作区→暂存区这套流程**，直接无视。

- 写在`.gitignore`里面的文件，就算你写`git add .`，git 也会跳过它，不会进收纳筐。

> 注意：只对**还没被 Git 追踪过的新文件生效**。 如果文件已经 commit 过了，之后再写进 gitignore 是拦不住的。

## 4. 汇总流程

工作区（你正在改文件） → `git add` → 暂存区 (收纳筐) → `git commit` → 本地 Git 档案室 (.git) → `git push` → GitHub 远程网页
